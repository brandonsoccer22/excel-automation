# Power Query in Excel desktop

Use the [WorkbookQuery object](https://learn.microsoft.com/en-us/office/vba/api/excel.workbookquery) and [M language reference](https://learn.microsoft.com/en-us/powerquery-m/). Query definitions, workbook connections, and load destinations are distinct objects.

1. Inventory `book.api.Queries` by name, formula, and description. Inventory worksheet query tables and workbook connections separately. Inspect downstream M references, including quoted identifiers, before renaming or deleting a query.
2. Create via `Queries.Add(name, m_source, description)`. Read or replace the M via `Queries.Item(name).Formula`. Preserve existing M before edits and prefer working on a copy. Review data sources, credentials, privacy boundaries, and output schema before refreshing.
3. Choose the required load destination. Use the helper from the skill's scripts directory, passing the target workbook's `.api`. The helper uses Excel's Mashup OLE DB provider, with `$Workbook$` as the data source and the query name as the location. Microsoft documents the generic COM entry points. Confirm the provider and load behavior against the installed Excel build.
   - **Worksheet** — use `load_worksheet(book.api, name, sheet.api, "A1")` on a clear sheet or a reserved area with space for expansion. Keep the returned ListObject and its QueryTable. For existing loads, refresh the existing QueryTable. Check headers, row count, representative values, and overflow. [ListObjects.Add](https://learn.microsoft.com/en-us/office/vba/api/excel.listobjects.add) · [QueryTable.Refresh](https://learn.microsoft.com/en-us/office/vba/api/excel.querytable.refresh)
   - **Data Model** — use `load_model(book.api, name, connection_name)` on a workbook that supports the model. Check that the returned connection reports `InModel`. Find its table through `book.api.Model.ModelTables` by matching `SourceWorkbookConnection.Name`. Compare `RecordCount` and validate data with a model-backed PivotTable or measure. Refresh existing model connections in place. [Connections.Add2](https://learn.microsoft.com/en-us/dotnet/api/microsoft.office.interop.excel.connections.add2?view=excel-pia) · [ModelTable source connection](https://learn.microsoft.com/en-us/office/vba/api/excel.modeltable.sourceworkbookconnection)
4. Prefer a targeted refresh. For a query-level refresh call `WorkbookQuery.Refresh()` and follow it with `Application.CalculateUntilAsyncQueriesDone()`. For a worksheet load use `QueryTable.Refresh(False)`. Review other connections before using `RefreshAll`, which may start background refreshes. For providers that still refresh in the background, check their exposed refresh state with a bounded wait. Completion alone does not verify the results. Recalculate dependent Excel formulas and compare actual data against known expected values.
5. Before removal, inspect dependent queries, connections, worksheet loads, model tables, charts, and pivots. Call `WorkbookQuery.Delete(False)` to retain the underlying connection or `Delete(True)` when its removal is intended. Inspect remaining artifacts after deletion. [WorkbookQuery.Delete](https://learn.microsoft.com/en-us/office/vba/api/excel.workbookquery.delete)

After saving, reopen the output and read the M through `Workbook.Queries`. Inspect the persisted connection and destination. In a disposable copy, change the M again, refresh, and assert the expected change in Excel.
